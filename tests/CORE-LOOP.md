# Shiny Village 핵심 학급 흐름

학생은 상추밭에서 시작한다. 누적 수확 16개가 되면 과수·물가 중 전문 역할 하나를 고를 수 있고, 80개가 되면 목장 역할도 선택할 수 있다. 전문 역할은 한 번 선택하면 유지되며, 기존 밭·재고·공부 기록은 그대로 남는다. 교사는 학급 날짜와 협력 이야기 시작을 관리한다.

| 장소 | 학생이 하는 일 | 저장·연결 |
| --- | --- | --- |
| 농장 | 심기 → 물 주기 → 수확, 밭 확장 | 개인 밭·재고·누적 수확을 서버에 저장 |
| 과수 직업 활동 | 수확 16개 뒤 역할 선택 → 사과 생산 | 사과가 보관함·장터·급식 이야기 재료로 이어짐 |
| 목장 | 수확 80개와 100코인 뒤 젖소 입양 → 먹이·물 → 우유 | 우유가 보관함·장터·급식 이야기 재료로 이어짐 |
| 물가 | 수질 확인 → 돌봄 → 생선 수확 | 생선이 냉장창고로 들어간 뒤 포장·안전 점검·배송·장터 인계를 거쳐 교환·급식 이야기 재료로 이어짐 |
| 장터 | 마을에서 걸어가기 → 친구 제안 수락 | 두 학생의 재고를 서버에서 한 거래로 변경 |
| 협력 이야기 | 운송·전력 복구 → 네 재료 기부 → 품질 검수·급식 인계 | 학급 공동 진행과 학생 기여를 서버에 저장 |
| 별빛도서관 | 30석 중 선택 → 공부 시작·휴식·마무리 | 좌석과 공부 기록을 서버에 저장 |

냉장 배송은 서버에 저장되는 실제 재고 단계이며, 배송 중 수량은 보관함과 장터에서 사용되지 않는다. 배송 차량은 이 상태를 보여 주는 시각화다. 실제 교환은 장터에서, 이야기의 길·전력 복구 판정은 직업 미션에서 일어난다. 수질 지표는 교육용 시뮬레이션이다.

자동 검사: `role-specialization.mjs`는 네 재료가 실제 획득 경로를 거쳐 급식 이야기로 모이는지 검사한다. `role-specialization-browser.cjs`와 `role-place-browser.cjs`는 메뉴→전문 역할 선택→실제 일터를 검사한다. `story-browser.cjs`는 폭우에서 급식 완성까지의 현재 학생 화면을 검사한다. 자원 기부 동시성은 `story-test.mjs`가 별도 테스트 DB의 재료 준비값으로 검사한다. 목장·물가·장터·유통·재난·도서관의 개별 브라우저 검사는 각각 해당 테스트 파일에 있다.

모든 브라우저 검사는 `TEST_URL=http://127.0.0.1:<port>`와 `TEST_DB=test-output/<isolated>.sqlite`로 실행한다. 로컬의 120개 HTTP 요청 검사는 계정·요청 처리 확인이며, 교실의 120대 기기 동시 접속 보장은 아니다.
