# 함께 만나는 장터 — 구현과 검증

2026-09-27

## 구현

- 기존 다섯 탭과 우리 마을 → 장터 경로 유지.
- 같은 학급의 실제 장터 방문자만 캐릭터로 표시. 체험 친구는 실제 방문자로 가장하지 않고 가판대에 표시.
- 광장 자리 선택으로 캐릭터 이동, 친구·가판대 선택으로 물건 보기.
- 서버에 전송되는 준비된 인사 3종. 자유 채팅 없음. 인사 간격 최소 5초.
- 판매자가 물건을 맡기며 동의하고 구매자가 내용 확인 후 수락하는 기존 거래 모델 유지. 기존 commands 트랜잭션·중복 방지 사용.
- 물건을 맡기고 떠난 학생은 ‘물건만 맡김’으로 표시. 교환은 계속 가능.
- 약 8~11초 완료 기반 방문 갱신. 퇴장·다른 탭·페이지 숨김 시 퇴장 요청. 요청 실패·강제 종료 시 마지막 방문에서 35초가 지난 뒤 조회 목록에서 제외.
- 방문자 많은 경우 PC 6명, 휴대폰 3명 단위 이웃 페이지. 전체 방문 인원은 상단에 표시. 모두를 한 화면에 겹쳐 그리지 않음.
- 최소 공개 정보만 반환: 학생 식별자·별명·광장 자리·인사. 학급 서버 인증으로 조회 범위 제한.

## 테스트

1. `tests/market-presence.cjs`: 구현 전 `/api/market-presence` 404로 실패 확인. 구현 후 입장, 두 방문자, 인사, 입력 검증, 교사 접근 거절, 학급 분리, 퇴장, 교사 일시정지 통과.
2. `tests/market-square-browser.cjs`: PC 1360px와 휴대폰 390px 브라우저에서 동시 방문, 인사 전달, 이동, 교환 후 양쪽 재고, 퇴장·재입장·새로고침 검사. 실제 재배 시간으로 당근 준비. 테스트 클래스 종료 후 일시정지.
3. 기존 `stage1-view-switch.cjs` 4개와 `stage3-navigation.cjs` 4개 통과. 기존 농장/마을 전환과 다섯 탭 경로 회귀 검사.
4. `tests/market-presence-load.cjs`: 로컬 4학급×30명, 방문 120개 동시 요청 통과. 각 학급 30명만 반환하고 민감 상태를 내보내지 않음.

## 한계

실시간 소켓 동기화가 아니라 주기적 갱신이다. 친구의 이동·인사가 즉시 보이지 않을 수 있다. 한 브라우저에서 동일 계정을 여러 탭에 열면 방문 표시가 마지막 요청에 따라 바뀔 수 있으므로 학생별 한 탭을 사용한다. 로컬 API 120개 요청은 실제 학교 네트워크나 120개 브라우저의 성능 보증이 아니다. 인사와 이동은 보상을 지급하지 않는다.
