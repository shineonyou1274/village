# 120명 부하 검증 — 2026-09-27, 온라인 v36

## 결론
120개의 테스트 계정이 입장·농사·공부·기부를 수행하고 기록을 유지하는 것은 확인했다. 그러나 요청이 몰리면 지연과 연결 실패가 발생하므로 “병목 없음” 또는 “120대 교실 운영 준비 완료”로 판정하지 않는다.

온라인 재검사의 95% 응답 시간(클라이언트 대기열 시간 포함): 입장 3.31초, 심기 2.44초, 물 주기 3.04초, 공부 시작 3.78초, 수확 3.29초, 마을 조회 7.34초, 성장 조회 8.22초, 공부 상태 저장 8.59초. 최대 8.85초.

### 검사 내용
- 새 테스트 학급 4개, 각 30명. 기존 학생 계정·기록은 사용하지 않았다.
- 120명 동시 입장, 각자 1번 밭 심기·물 주기·수확.
- 120개 공부 세션 및 중복 없는 자리. 15초 간격의 동기화된 혼합 조회 4회.
- 친구 목록에 개인 공부 목표가 노출되지 않는지 확인.
- 기부 명령 120개를 한 번씩 재전송해 총 240번 요청. 학생당 기부는 한 번만 반영되고 각 반 기부량은 30개, 개인 잔여 작물은 1개인지 확인.
- 종료 후 테스트 공부 세션을 취소하고 온라인 테스트 학급은 일시정지했다.

### 해석과 다음 점검
동시 요청 제한은 검증 도구에 적용한 조건이며 실제 앱에 새 제한을 배포한 것이 아니다. 실패 없는 재검사만으로 처음의 연결 실패를 서버 또는 클라이언트 탓으로 확정할 수 없다. 첫 검사는 120명이 각자 조회·성장·공부 저장을 동시에 실행하는 강한 스트레스 조건이다. 실제 앱은 화면에 따라 호출이 달라지고 농장 조회는 10–15초 간격이다.

다음 개선 대상은 폴링 요청 분산, 현재 화면에 필요 없는 조회 감소, 연결 실패 때 중복 적립 없이 복구되는 흐름이다. 서버 로그와 다른 송신 환경을 대조해야 연결 실패의 원인을 확정할 수 있다. 이후 실제 학교 기기와 Wi-Fi에서 30명→60명→120명 순으로 수업 동작을 확인해야 한다.

이 검사는 한 PC의 HTTP 가상 사용자 시험이다. 120개의 렌더링 브라우저, 저사양 단말 프레임률, 학교 Wi-Fi, 이미지 첫 로딩 시간, 장시간 수업 안정성 및 장터 경합 전체를 검증하지 않았다.
