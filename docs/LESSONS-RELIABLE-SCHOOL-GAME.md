# Shiny Village 개발 회고와 재사용 지침

작성: 2026-09-27. 비슷한 교육용 게임을 만들거나 이 프로젝트를 수정하기 전에 읽는다.

## 가장 큰 교훈

기능을 추가하는 속도보다 학생이 이해하고 끝까지 수행할 수 있는 흐름이 중요했다. 버튼, 말풍선, 별도 페이지를 덧붙이면 기능은 늘지만 화면의 규칙이 깨진다. 먼저 화면·상태·이동 구조를 정하고, 작은 변경마다 기존 행동이 유지되는지 검증한다.

## 다음 작업에서 지킬 원칙

1. **구현과 계획을 구분한다.** 그림이 있다고 기능이 있는 것은 아니다. 화면 표시, 서버 동작, 저장, 학생 조작까지 연결되어야 구현 완료다. 예정지는 ‘준비 중’으로 표시하고 작동하는 시설처럼 안내하지 않는다.
2. **화면 이동의 기준을 하나로 둔다.** 모든 기기에서 내 농장·우리 마을·활동·별빛도서관·내 여권의 다섯 탭을 유지한다. 장터는 우리 마을 안에 둔다. 탭, 주소, 새로고침, 뒤로 가기가 같은 화면을 가리켜야 한다.
3. **지도 그림과 클릭 영역은 같은 좌표에서 계산한다.** 밭의 그림, 번호, 선택 영역, 작물, 캐릭터 도착점이 서로 다른 계산을 쓰면 빈 땅을 눌러 작업하게 된다. 확대·회전·크기 변경 뒤에도 같은 밭이어야 한다.
4. **화면 전환은 애니메이션에 의존하지 않는다.** 이전 화면 요소를 즉시 숨기고 새 화면 크기를 측정한 뒤 카메라와 캔버스를 갱신한다. 프레임이 늦어져도 농장 조작부가 마을에 남으면 안 된다.
5. **처음에는 한 가지 행동만 가르친다.** 밭 선택→심기→물 주기→수확을 먼저 경험하게 한다. 선택한 대상의 설명만 작은 패널에 표시한다. 여러 말풍선, 반복 안내, 모든 잠금 조건을 동시에 펼치지 않는다.
6. **서버 기록과 화면 기록의 의존성을 추적한다.** 여권 화면이 둘이라고 저장도 둘인 것은 아니다. 통합 전에 읽기·쓰기 API를 확인한다. 요청 수를 줄일 때도 그 응답을 사용하는 모든 화면을 조사한다. API 성공만으로 화면 갱신까지 검증했다고 하지 않는다.
7. **학생 데이터가 섞이지 않도록 검사한다.** 학생별 밭·재고·돈, 학급 공통 수업일, 실제 날짜를 사용하는 공부 기록을 구분한다. 로그아웃 후 다른 학생 입장, 교사 권한, 새로고침을 함께 검사한다. 중복 요청이 중복 보상을 만들지 않아야 한다.
8. **검증은 수정 전에 실패하는 것부터 확인한다.** 사용자 오류를 재현하는 테스트를 먼저 만든다. 수정 후 통과와 인접 흐름의 회귀 여부를 확인하고 단계별 배포한다. 단순히 버튼이 존재하는 테스트로 시각적 오류가 해결됐다고 판단하지 않는다.
9. **성능 결과에 조건을 붙인다.** API 동시 접속, 실제 브라우저 렌더링, 교실 와이파이는 별개다. 최대 동시 요청 제한을 둔 결과와 제한 없는 결과를 혼합하지 않는다. 실패율뿐 아니라 지연 시간도 보고한다. ‘120명 테스트 성공’을 ‘병목 없음’으로 표현하지 않는다.
10. **실제 기록을 보존한다.** 테스트 전용 학급을 사용하고 끝나면 세션을 정리한다. 문서에는 입장 코드·비밀 키를 넣지 않는다. 데이터 변경 전 호환성과 복구 방법을 정한다.

## 다음 수정의 필수 회귀 사례

- 농장→마을→농장 왕복: 지도와 조작부가 각 화면에만 표시되는가.
- 밭 1~6의 실제 그림을 선택: 선택 번호, 서버 작업 대상, 작물 모습이 일치하는가.
- 수확 직후 해금 기준 도달: 다른 탭을 방문하지 않아도 새 씨앗 버튼이 활성화되는가.
- 젖소 입양·먹이·물·우유: 행동 직후 돌봄 버튼과 상태가 갱신되는가.
- 새로고침·뒤로 가기: 주소와 화면, 재고, 밭 상태가 유지되는가.
- 휴대폰 터치·키보드·마우스: 동일한 작업을 수행할 수 있는가.
- 체험 학생·실제 학급·교사: 각 역할의 입장과 복귀가 가능한가.

## 2026-09-29 추가: 통과 개수보다 학생의 완주 경로

농장 검사 44개 통과만으로 장터까지 정상이라고 말할 수 없었다. 배포 전에는 체험 입장 → 씨앗 심기 → 물 주기 → 수확 → 우리 마을 → 장터까지 걷기 → 연습 친구의 제안 수락 → 새로고침 후 재고 유지 경로를 반드시 포함한다. `tests/trial-market-journey.cjs`가 이 경로를 실제 UI로 실행한다.

- 일반 브라우저와 숨김으로 보고되는 웹뷰 상태를 구분한다. 체험·학급 모두 가려진 화면에서는 연결과 이동을 쉬고, 복귀하면 재연결한다. 숨김 상태를 정상 이용 중 오류로 단정하지 않는다.
- 장터 도착을 애니메이션 프레임에만 의존시키지 않는다. 실제 위치와 경과 시간으로 도착을 판단한다.
- 전체 지도/광장/연결 대기/수업 일시정지/로컬 농사 모드별 안내를 실제 가능한 조작에 맞춘다.
- 알림은 DOM에 존재하는지만 확인하지 말고, 사용자가 스크롤하지 않은 현재 화면 안에 보이는지 검사한다.
- 테스트 전용 학급에서 기존 공동 이동·인사·학급 격리와 농장 회귀 검사도 통과한 뒤 배포한다.

2026-09-30 정정: 숨김 상태에서 이동이 차단되는 것은 정상 설계다. 미배포 v46의 체험 예외는 되돌리고, `tests/plaza-visibility.cjs`로 숨김 안내·중단과 복귀 후 실제 이동을 검사한다. 장터 교환 완주 검사는 `document.hidden === false`를 확인한 화면에서 수행한다.
